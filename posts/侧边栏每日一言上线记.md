# 给博客侧边栏加了个每日一言，每天一句不重样

博客侧边栏一直空着一块，想着放点轻量的东西。最后选了「每日一言」——每天自动来一句，文学、诗词、哲学混着来，访客看着不累，我自己也喜欢偶尔瞄一眼。

<!-- 在这里插一张侧边栏每日一言组件的截图，建议截深/浅两套主题，alt 写上"侧边栏每日一言组件" -->

做完了，跑在 Hitokoto 一言 API 上，纯前端直连，不用后端、不用花钱。这篇记一下怎么接进 Mizuki 的，以及上线时踩的一个让我白高兴的坑。

## 为什么选 Hitokoto

每日一言的数据源其实有好几个，对比了一圈：

- **Hitokoto 一言**：2016 年做到现在，最老牌，语料杂（动漫、网络、游戏、诗词、哲学都有），关键是官方 API 原生支持 CORS，前端直接 `fetch` 就能用，国内也连得上。
- **今日诗词**：古诗词为主，按季节和时间智能推荐，偏文艺。也有官方 JS SDK，自带跨域处理。
- **自建语料**：自己攒一个 txt 随机读，完全可控，但得自己维护句子，懒人劝退。

我这种想零成本、国内可直连、又偏好成熟方案的人，**Hitokoto 直接胜出**。诗词那套留着以后哪天想换风格再说。

## Mizuki 侧边栏的 widget 机制

Mizuki 的侧边栏不是写死一堆 HTML，而是一套 widget 系统：每个组件有个 `type` 字符串，配置里声明要哪些、排什么顺序，框架去查表渲染。这意味着加新组件是**增量扩展**，不用去动任何现有组件。

真正要碰的就几个地方：

```ts
// 1. 类型声明：src/types/config.ts
//    WidgetComponentType 里加一个 "hitokoto"

// 2. 路径映射：src/utils/widget-manager.ts
//    WIDGET_COMPONENT_MAP 加一条
//    hitokoto: "../components/widgets/hitokoto/Hitokoto.astro"

// 3. 注册到左栏：src/config/sidebarConfig.ts
//    components.left: ["profile", "announcement", "tags", "card-toc", "hitokoto"]

// 4. 渲染映射：src/components/layout/SidebarColumn.astro
//    componentMap 里加 hitokoto: Hitokoto  ← 这个最关键，详见后面踩坑
```

## 组件本体

新建 `src/components/widgets/hitokoto/Hitokoto.astro`，套一层主题自带的 `WidgetLayout`（标题栏、动画全免费送），里面就两件事：拉一句话、渲染。

```astro
---
import { Icon } from "astro-icon/components";
import WidgetLayout from "../common/WidgetLayout.astro";

// 分类：文学 d / 诗词 i / 哲学 k，偏文艺
const CATEGORIES = "c=d&c=i&c=k";
---
<WidgetLayout name="每日一言" id="hitokoto">
  <div class="hitokoto-widget">
    <p class="hitokoto-text" id="hitokoto-text">正在加载一句话…</p>
    <div class="hitokoto-foot">
      <span class="hitokoto-from" id="hitokoto-from"></span>
      <button class="hitokoto-refresh" id="hitokoto-refresh" title="换一句">
        <Icon name="material-symbols:refresh" />
      </button>
    </div>
  </div>
</WidgetLayout>
```

脚本部分也很直白：加载时拉一句，右下角那个圆形刷新按钮点一下换一句，API 挂了就显示一句兜底文案，不白屏。

```js
const CAT = "c=d&c=i&c=k";
const FALLBACK_TEXT = "愿你被这个世界温柔以待。";

async function fetchHitokoto() {
  const res = await fetch(`https://v1.hitokoto.cn/?${CAT}&encode=json`);
  const data = await res.json();
  return { text: data.hitokoto, from: data.from ? "—— " + data.from : "" };
}
// 加载/点击 → fetch → 渲染；失败走兜底
```

样式上跟主题对齐了：字号、行高用了主题的文字色变量，深色模式自动切；刷新按钮 hover 变主题色，还会转一圈。连 `prefers-reduced-motion` 都照顾了，关动画的人不会被转圈烦到。

:::tip
想换内容风格很简单：把组件里和脚本里的 `c=d&c=i&c=k` 删掉就是全随机；想纯诗词就只留 `c=i`。隐藏出处把 `SHOW_FROM` 设成 `false` 就行。位置在 `sidebarConfig.ts` 的 `components.left` 数组里调顺序。
:::

## 踩坑：组件上线了却不显示

改完四个接入点，本地起了 dev server，首页 HTML 里能 grep 到 `hitokoto` 字样，我以为成了，美滋滋推上线。

结果线上一看——没有。

排查才发现，Mizuki 渲染侧边栏真正认的，是 `SidebarColumn.astro` 里一份**静态映射表 `componentMap`**：

```ts
const componentMap = {
  profile: Profile,
  announcement: Announcement,
  // ... 一堆组件
  calendar: Calendar,   // ← 到这就没了，没有 hitokoto
};
```

我前面改的四处，配置的、类型声明的、路径的，全齐了，**唯独漏了这张真正干活的渲染表**。结果就是：组件被编译进去了（所以 CSS、JS 里都有 `hitokoto` 字符串），但渲染时查不到映射，直接返回 `null` 跳过，页面上啥也没有——典型的"静默失败"，不报错但也没东西。

补上 `import Hitokoto` 和 `componentMap` 里的 `hitokoto: Hitokoto` 两行，重新推，刷新页面，卡片这才真出来了。

:::warning
给 Mizuki 加侧边栏组件，**至少动五处**：类型、路径映射、配置注册、渲染映射（`SidebarColumn.astro`）、组件本体。前几处只管"认不认得这个 type"，最后那处才管"画不画得出来"。别像我一样只改了配置就以为万事大吉。
:::

## 验证

- **本地**：dev server 起来后，首页 HTML 里出现 `data-id="hitokoto"`，确认真的渲染了（不是只有字符串）
- **线上**：推完等 Vercel 构建完，强刷（Ctrl+F5）一下就能看到侧边栏底部那张卡片，带一句出处，右下角能换

现在每次打开博客，左下角都会有一句不重样的话。哪天看腻了换成诗词，或者挪到公告下面，都是十分钟内的事。
