# 看板娘升级记：给博客装一个会聊天、会介绍页面的 AI 猫耳娘

## 为什么要折腾

我的博客（Mizuki 主题，Astro 框架）一直挂着一个 Live2D 看板娘，能眨眼、能卖萌，但也仅此而已——你摸她，她回你几句固定话；你想跟她聊两句，她一句也接不上。

于是决定给她升级一下，目标三个：

1. **能 AI 聊天**：接入 DeepSeek，访客可以跟她对话，还能回答"这篇文章讲了什么"
2. **会介绍页面**：鼠标悬停到导航、文章卡片上，她能像导游一样说说这是啥
3. **人设可配置**：性格、语气、自我介绍全部扔进一个 JSON，改完即生效

折腾了两天，最终版跑通了。这篇只讲**最终成功版本**，中间的弯路和死胡同就不重复踩了。

:::note
前提：博客是 Astro 静态站，部署在 Vercel。如果你用别的框架，思路一样，改改接入方式就行。
:::

## 最终方案的架构

核心思路：**看板娘本体（渲染）和 AI 逻辑完全解耦**。

```
┌──────────────────────────────┐
│  主页面（Astro）               │
│  ┌────────────────────────┐  │
│  │ Pio.astro              │  │
│  │  ├─ iframe(live2d-host)│  │  ← 看板娘渲染
│  │  └─ waifu-chat.js      │  │  ← AI 聊天 + 悬停介绍
│  └────────────────────────┘  │
│         │ postMessage 通信    │
│         ▼                     │
│  ┌────────────────────────┐  │
│  │ api/chat.js (Vercel)   │  │  ← Serverless 代理
│  └────────────────────────┘  │
│         ▼                     │
│  ┌────────────────────────┐  │
│  │ DeepSeek API           │  │
│  └────────────────────────┘  │
└──────────────────────────────┘
```

几个关键决策：

- **看板娘本体**：`Pio.astro` 里放一个 iframe，加载 `live2d-host.html`，里面跑 l2d-widget 库
- **AI 聊天和悬停介绍**：放在 iframe **外面**（主页面），因为它们要访问页面 DOM（抓文章内容做 RAG）
- **两者通信**：全靠 `postMessage`，iframe 内是纯渲染，不碰 AI 逻辑
- **API 代理**：`api/chat.js` 是 Vercel Serverless 函数，把请求转发给 DeepSeek，**API Key 只藏在服务端**

## 功能一：AI 聊天（DeepSeek）

### 服务端代理

Astro 是静态站，没法直接写 API 路由。但 Vercel 原生支持根目录的 `api/` 文件夹当作 Serverless 函数，不影响静态构建：

```js
// api/chat.js
export default async function handler(req, res) {
  if (req.method !== "POST") return res.status(405).json({ error: "Method not allowed" });

  const apiKey = process.env.DEEPSEEK_API_KEY;
  if (!apiKey) return res.status(500).json({ error: "DEEPSEEK_API_KEY not configured" });

  const { messages } = req.body;
  const response = await fetch("https://api.deepseek.com/chat/completions", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ model: "deepseek-chat", messages, stream: false }),
  });

  return res.status(response.ok ? 200 : response.status).json(await response.json());
}
```

部署后在 Vercel 的 Environment Variables 里加一个 `DEEPSEEK_API_KEY` 就完事。

### 前端聊天核心

聊天窗口是自建的（`waifu-chat.js` + `waifu-chat.css`），要点几个：

**打字动画不闪烁**——这是坑得最深的地方。最初每打一个字就重建整个消息列表 DOM，聊天窗口疯狂闪。最终方案是**只更新最后一条气泡的 innerHTML**：

```js
async _typeAnimation(fullText) {
  const lastBubbleEl = this.msgContainer.querySelector(
    ".mizuki-chat-msg.assistant:last-child"
  );
  let idx = 0;
  while (idx < fullText.length) {
    idx = Math.min(idx + 2, fullText.length); // 每帧打 2 字
    lastBubbleEl.innerHTML = this._simpleMd(fullText.substring(0, idx));
    await new Promise((r) => setTimeout(r, 20));
  }
}
```

**RAG 抓当前文章**——AI 能回答"这篇文章讲了什么"，靠的是把页面正文塞进请求：

```js
const pageCtx = document
  .querySelector(".markdown-content, article, main")
  ?.textContent.replace(/\s{3,}/g, "\n").trim()
  .slice(0, 2000);

const messages = [
  { role: "system", content: this.cfg.systemPrompt },
  ...history,
  { role: "user", content: `【当前页面内容】\n${pageCtx}\n\n【用户问题】${msg}` },
];
```

**明暗模式自适应**——聊天窗口一开始写死深色底白字，白天模式完全看不清。后来发现博客主题的 CSS 变量 `--float-panel-bg`、`--deep-text` 是明暗两套的，但 `--deep-text` 只定义了一个值（夜间不切换）。最终自己定义了一组 `--chat-*` 变量，夜间强制白字：

```css
#mizuki-chat-box {
  --chat-bg: var(--float-panel-bg);
  --chat-text: var(--deep-text);
  /* ... */
}
:root.dark #mizuki-chat-box {
  --chat-bg: oklch(0.19 0.015 var(--hue));
  --chat-text: rgba(255, 255, 255, 0.92); /* 夜间白字 */
}
```

### 💬 按钮融入看板娘菜单

聊天入口按钮没有自己画，而是**塞进 l2d-widget 自带的菜单栏**，和"休眠""关于"按钮排成一列。做法是用 l2d-widget 的 `extraItems` 配置：

```js
widgetConfig.menus = {
  extraItems: [{ icon: "mdi:message-text-outline", label: "聊天", action: "chat" }],
};
```

l2d-widget 会自动把它渲染成菜单按钮，样式完全统一。点击后通过 postMessage 通知主页面开合聊天框，按钮图标在 💬 和 ✕ 之间切换。

:::tip
这里有个坑：切换按钮 title 后，原来用 `button[title="聊天"]` 就查不到按钮了，关闭时无法恢复。解决方法是查找时同时匹配两种 title 状态。
:::

## 功能二：人设可配置

性格、语气、自我介绍全部集中在 `public/pio/waifu-chat.json`：

```json
{
  "person": {
    "name": "诺瓦",
    "role": "博客看板娘",
    "personality": ["胆小怕生", "熟悉后黏人", "重度甜食控"],
    "tone": ["软萌", "带'喵'口癖", "害羞会结巴"],
    "rules": ["回答要简短有趣", "主动关心主人的心情"]
  },
  "welcomeMsg": "🐾 欢迎光临喵~"
}
```

前端读取后**自动拼成 system prompt**，不用手写：

```js
function buildSystemPrompt(person) {
  return [
    `你是一个叫「${person.name}」的${person.role}，住在博客「${person.home}」里。`,
    person.selfIntro,
    `你的性格：${person.personality.join("、")}。`,
    `你的说话语气：${person.tone.join("、")}。`,
    ...(person.rules || []),
  ].join("\n");
}
```

改人设 = 改 JSON，不用碰代码。

## 功能三：页面元素悬停介绍

参考开源项目的 `waifu-tips.json` 思路，做了一个纯配置驱动的悬停介绍系统：

```json
{
  "mouseover": [
    { "selector": "#navbar-links-container a[href='/archive/']",
      "text": ["归档页喵，所有文章都按时间排好啦~", "想翻旧文？诺瓦带你逛喵~"] },
    { "selector": "a[href^='/posts/']",
      "text": ["这篇是「{text}」，点进去看看吧~"] }
  ],
  "pageTransition": ["欢迎来到新页面喵！", "这一页也有宝藏哦~"]
}
```

两个细节：

- **多份句子随机弹**：每个元素的 `text` 是数组，悬停时随机挑一条，不单调
- **`{text}` 占位符**：文章卡片悬停时自动填入标题，"这篇是「我的第一篇博客」，点进去看看吧"——每篇文章都有自己的句子，不用为每篇单独配置

页面切换（SPA 路由跳转）也监听 swup 的 `visit:end` 事件，从 `pageTransition` 数组随机弹一条欢迎语。

:::note
原本想用 RAG + AI 实时生成页面介绍，但抓取不稳定、还烧 token，最终放弃，全部改成静态配置。又省钱又稳定。
:::

## 功能四：点击看板娘触发触摸句子

原来看板娘的触摸提示（"你在干什么呀？"）是**定时自动循环**弹的，访客还没摸她就自言自语，还和悬停介绍抢气泡。最终改成：**关掉自动循环，只有点击/触摸看板娘时才随机弹一句**。

关闭自动循环的写法有点隐蔽，l2d-widget 对没传的 `messages` 会用默认值兜底，必须**显式传空数组**：

```js
tipsData.messages = [];
tipsData.interval = 2147483647; // 极大值，定时器几乎永不触发
```

然后把触摸句子通过 `_touchMessages` 传给 iframe，点击 canvas 时随机取一条显示。

## 总结

最终版看板娘有这些能力：

- ✅ **AI 聊天**：DeepSeek 驱动，能答文章内容（RAG），打字动画流畅不闪
- ✅ **人设可配置**：性格/语气/自我介绍全在 JSON，改完刷新即生效
- ✅ **页面元素悬停介绍**：导航、文章、按钮各有专属句子，多份随机
- ✅ **页面切换欢迎**：SPA 跳转后自动弹一句
- ✅ **点击触发触摸句**：不再自动自言自语，不抢气泡
- ✅ **明暗模式自适应**：白天黑夜都看得清

几个值得记住的经验：

1. **静态站要接 AI，用 Vercel Serverless 代理最省事**，Key 藏服务端，构建不受影响
2. **iframe 内外通信靠 postMessage**，渲染和逻辑解耦，改一处不炸另一处
3. **l2d-widget 的配置有默认值兜底**，想关掉某个功能要显式传空值，不然你以为关了其实还在跑
4. **public 下的 JSON 配置请求要加时间戳防缓存**，不然改完配置老设备还在用旧版
5. **复用原生气泡比自己造轮子省心**，代价是得摸清它的内部 DOM 特征

升级完，博客的看板娘终于不是个只会眨眼的摆设了。她现在叫诺瓦，一只猫耳娘，会陪访客聊天，会介绍每篇文章，还会在切页时热情欢迎。来我博客逛逛，找她聊两句？
